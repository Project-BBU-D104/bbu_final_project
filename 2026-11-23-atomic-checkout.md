# Atomic, Retry-Safe Checkout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cashier who loses the checkout response can retry the confirmed cart and recover its receipt. The database records one invoice, one initial payment and one stock deduction.

**Architecture:** Give the POS one authenticated checkout endpoint. Claim the checkout ID, write the business records and store the original receipt in the same database transaction. Flutter saves the confirmed request before sending it and uses the returned receipt for both display and PDF export.

**Tech Stack:** FastAPI, SQLModel, SQLAlchemy 2.0.45, Alembic, MySQL/InnoDB, pytest, Flutter, GetX, GetStorage and flutter_test.

**Spec:** [improve.md, implementation order, item 2](improve.md#implementation-order). The [warehouse-allocation plan](2026-11-23-sale-warehouse-allocation.md) defines the stock and cart interfaces used here.

## Global Constraints

- “Commit the sale, initial payment, and stock deduction in one transaction. Reuse the same checkout ID after a timeout.”
- “Disable sold-out items, cap quantities at available stock, surface specific stock errors, and show the persisted invoice number and lines on the receipt.”
- Preserve checkout confirmation, busy states, labeled Back navigation, existing sales history and subsequent payment management. Use the shared Flutter UI kit and English/Khmer translations.
- Build on item 1's warehouse migration, locked deduction helper, catalog `warehouse_availability`, and cart keyed by product and warehouse. At planning time the catalog exposes the breakdown and the allocation migration is in the working tree, while the Flutter checkout still submits product and quantity alone. Integrate the relevant item 1 changes before implementing the dependent tasks.
- Run Python commands from `backend/` with its environment active and Flutter commands from `frontend/`. Commit implementation and tests only. Keep this plan out of commits and pushes per [CLAUDE.md](CLAUDE.md).

## Review Focus

1. A response disappears **after commit**, even for the last units on hand. Retrying returns the original invoice and lines. Tasks 1 and 3.
2. The initial payment fails after stock and lines have been flushed. All writes roll back, and the same ID can subsequently succeed. Task 1.
3. Two database sessions overlap. Matching requests converge on one receipt, different carts cannot oversell, and a reused key cannot expose a different cashier's receipt. Task 1.
4. Displayed warehouse stock goes stale. Every add path respects the known limit, and the server explains a shortage so the cashier can correct the line. Tasks 1 and 2.
5. The app reopens after a timeout, or catalog prices or names change before replay. The original cashier can recover the confirmed checkout and export its recorded lines. Tasks 1 and 3.

### Task 1. Commit and replay one paid checkout

**Interfaces.** Add `POST /sale/checkout/` returning HTTP 200 on first success and replay. Accept `CheckoutCreate(checkout_id, customer_id, payment_type_id, expected_total, sale_items)`. Use a 32-character lowercase random hex ID, positive integer IDs, a positive two-decimal amount and at least one line with required positive integer `product_id`, `warehouse_id` and `qty`. Reject duplicate product/warehouse pairs and extra request fields. Derive the cashier from `get_current_user`. Expose `checkout_sale(session: Session, request: CheckoutCreate, user_id: int) -> CheckoutReceipt`.

**Receipt contract.** Return `checkout_id`, `sale_id`, `invoice_no`, `customer` (name), `payment_method`, `payment_date` (UTC), `reference_no`, `subtotal`, `total` and `lines`. Each line contains `product_id`, `product_name`, `warehouse_id`, `qty`, `sale_price` and `subtotal`. Serialize money as two-decimal strings. This is the receipt for the original transaction, including when the invoice is subsequently edited or reversed.
